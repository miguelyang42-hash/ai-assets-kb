## Workflow
1. **环境准备与协议定义**：在项目根目录创建 `pending_assets/` 作为临时上传区，`static/assets/` 作为最终存储区。定义元数据 JSON 标准，必须包含 `department`, `keywords`, `version` 等字段，并确保文件名符合 `{Category}_{SubType}_{Date}_{Desc}.{ext}` 规范。
2. **编写同步脚本 (sync_assets.py)**：创建 Python 脚本，核心逻辑包括：遍历 `pending_assets/`，读取同名 `.json` 元数据文件；**关键步骤**：使用 `encoding='utf-8-sig'` 打开 JSON 文件以兼容 Windows PowerShell 默认生成的 BOM 头；根据元数据将文件移动至 `static/assets/{department}/` 并重命名。
3. **自动生成展示页与 API**：脚本需同时在 `docs/{department}/` 下生成对应的 Markdown 文件，引用新资产链接。最后，聚合所有资产的元数据生成 `static/api/assets.json`，为 AI 员工提供轻量级检索接口。
4. **执行与验证**：运行脚本后，检查 `static/assets/` 中的文件结构是否符合预期，并确认 `docs/` 下新生成的页面能在 Docusaurus 侧边栏中正确显示（依赖 `sidebars.ts` 的自动生成配置）。

## Suggestions
- 在 `docusaurus.config.ts` 中确保 `presets[0].docs.sidebarPath` 指向正确的侧边栏配置文件，并启用自动生成模式以减少手动维护成本。
- 对于大型视频文件，建议在脚本中加入大小检查，超过阈值时仅生成元数据记录而不移动实体文件，改用外部 CDN 链接。

## Fallback / Edge Cases
- Step 2: 如果 JSON 解析失败，首先检查文件编码是否为 UTF-8 BOM。若报错 `Unexpected UTF-8 BOM`，必须将读取编码改为 `utf-8-sig`。
- Step 3: 若 `sidebars.ts` 未配置为自动生成，新创建的 Markdown 页面可能不会出现在导航中。此时需手动更新 `sidebars.ts` 或将其修改为 `type: 'autogenerated', dirName: '.'`。

## Pitfalls
- Step 2: Windows PowerShell 使用 `Out-File` 或重定向符号创建的 UTF-8 文件通常带有 BOM 头，Python 默认的 `utf-8` 解码器会因此报错，必须显式使用 `utf-8-sig`。
- Step 4: 在移动文件前务必校验目标路径是否存在，否则 `shutil.move` 可能会因目录缺失而中断整个同步流程。
