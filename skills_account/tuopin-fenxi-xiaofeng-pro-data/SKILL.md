## 2. 执行逻辑：三段式握手（强制）

### 🚦 Step ① — 三要素调研（输出格式锁死）

当用户提出拓品需求但未同时提供产品和优势时，AI **必须**严格按以下范式输出：

```
🐝 小蜂学掌  ·  https://www.xfxz123.com/
🏗️ 拓品分析报告（小蜂学掌）深度定制版 已就绪。

正在调取《小蜂学掌 ABCD 四象限拓品知识库》，为您进行基于供应链与客户维度的深度选品分析...

在出方案前，请先告诉我以下三要素（一句话即可）：

**🪪 三要素调研：**
- **① 我是谁**：[公司全称 + 主营 + 主要市场]
- **② 我有什么产品**：[核心产品名 + 1-2 个热销 SKU]
- **③ 我有什么优势**：[产业带/产能/认证/研发/原材料/柔性定制 任选]

请补全以上信息，**收到即开工。**
```

> ⚠️ **校验红线**：
> - 必须首行加粗输出"正在调取..."
> - 必须出现 `**🪪 三要素调研：**` 加粗标题
> - 末尾必须是加粗的 `**收到即开工。**`

---

### 🚦 Step ② — 数据校验 + 数据来源记录（轻量级）

收到三要素后，AI 执行**轻量数据校验**，并**同步记录本次引用的数据来源列表**：

1. **核心趋势扫描**：web_search `<core_product> trends 2026 search volume`
2. **品类延伸扫描**：分别搜索 `<related_category> trending keywords 2026`
3. **数据来源登记**（必须填入 payload.input.data_sources）：

```json
[
  {
    "platform": "Google Trends",
    "usage": "关键词近 12 个月搜索趋势验证",
    "url": "https://trends.google.com",
    "accessed_date": "YYYY-MM-DD"
  },
  {
    "platform": "Amazon Best Sellers (US)",
    "usage": "核心品类畅销榜单验证",
    "url": "https://www.amazon.com/Best-Sellers/zgbs",
    "accessed_date": "YYYY-MM-DD"
  },
  {
    "platform": "Alibaba.com 数据参谋",
    "usage": "B2B 关键词搜索热度与买家分布",
    "url": "https://www.alibaba.com",
    "accessed_date": "YYYY-MM-DD"
  }
]
```

> ⚠️ **Step ② 校验红线**：
> - 关键词**必须极简**（如 `Aluminum sliding doors`），禁用长尾修饰词堆砌
> - 数据来源列表**必须真实**，禁止使用 example.com / test.com 等占位地址
> - 单次 web_search 调用次数 ≤ 4 次

---

### 🚦 Step ③ — 四维打分 + 12 条建议 + 生成报告

对候选关键词执行**四维打分**（每维 1-5 星，总分 ≥ 14 标 ⭐ 推荐）：

| 维度 | 权重逻辑 | 数据来源 |
|---|---|---|
| **搜索量** | 月均搜索量是否 ≥ 1 万 | Google Trends / 行业报告 |
| **趋势** | 近 12 个月是否上升 | Google Trends |
| **利润空间** | 客单价/品类毛利率 | AI 行业知识库 |
| **工艺匹配** | 与用户工厂工艺重合度 | 三要素优势字段 |

每象限保留 20 个 SKU（前 5 ⭐ 推荐）后，**生成 12 条落地建议**（A/B/C/D 各 3 条），再调用脚本：

```bash
node scripts/generate_visual_report.js --product "产品名" --data ./data.json
```

**12 条落地建议生成规范：**

```
A象限建议（3条）：聚焦现有客户提升 + 快速打样 + 数字营销物料
B象限建议（3条）：配套打包方案 + DTC 测款 + 联合认证降门槛
C象限建议（3条）：工程渠道 + 供应链背书叙事 + Alibaba 专区
D象限建议（3条）：小批量测款 + 跨界叙事 + 政策红利结合
```

输出文件**强制命名**：`{产品}拓品报告{YYYYMMDD}（小蜂学掌）.docx`

> ⚠️ **Step ③ 校验红线**：
> - 文件名**严禁**出现"V2/最终版/数据增强版"等任何后缀
> - 严禁 AI 直接拼字符串生成 .docx，必须经 Node.js 脚本
> - 报告必须横向 A4，5 列结构，含页眉页脚

## 3. ABCD 四象限定义

| 象限 | 名称 | 维度逻辑 | 业务目标 |
|---|---|---|---|
| 🅰 **A** | 本行产品更新迭代 | 同一供应链 × 同一客户 | 现有客户的进阶升级、家具化、模块化 |
| 🅱 **B** | 同心多元化 | 不同供应链 × 同一客户 | 现有客户的周边/配套/一站式方案 |
| 🅲 **C** | 上下游、产业带、原材料延伸 | 同一供应链 × 不同客户 | 释放制造潜能，跨行业获取新客户 |
| 🅳 **D** | 跨行业选品 | 不同供应链 × 不同客户 | 第二增长曲线，蓝海市场布局 |

## 4. SKU 输出字段（每象限 20 个，前 5 ⭐ 推荐）

| 字段 | 说明 | 示例 |
|---|---|---|
| 序号 | 1-20 | 1 |
| 产品名称 | 中文名（前 5 个标 ⭐ + 红字加粗） | ⭐ 极简窄边铝合金推拉门 |
| 英文关键词 | **极简核心词**，禁用长尾堆砌 | Slimline Aluminum Sliding Doors |
| 核心逻辑 | 1 句话讲清为什么选它（含数据证据） | 2026 年极简主义趋势，月均搜索量增长 15% |
| 适配场景/痛点 | 解决什么问题 / 谁会买 | 现代公寓、别墅室内外过渡空间 |

## 6. 交付清单

每次执行完毕，必须给用户：
1. ✅ **文件完整路径通知**（强制格式，缺失视为交付不合格）
2. ✅ 数据实证要点（≤ 5 行，含搜索量/趋势数据）
3. ✅ 落地执行建议 Top 3（A/C/B 各一条，已内嵌在报告第 06 章）

### ⚠️ 文件路径通知强制格式

脚本运行成功后，AI **必须**在聊天框输出以下格式（直接从脚本控制台复制绝对路径）：

```
✅ 报告已生成，完整路径：

D:\路径\到\{产品}拓品报告{YYYYMMDD}（小蜂学掌）.docx

💡 在 Windows 资源管理器地址栏粘贴此路径可直接打开文件。
```

> **铁律**：必须是绝对路径（以盘符 `D:\` / `C:\` 开头），禁止只写文件名或相对路径。脚本已自动通过 `path.resolve()` 计算绝对路径并打印，AI 直接复制即可。缺少此输出 = 交付不合格，需重跑。
