## Preconditions
- 已确定目标产品关键词 `{product_keyword}` 及目标市场平台（如 Amazon, eBay）。
- 确保环境具备本地文件写入权限或已识别可写入的工作区目录。

## Workflow
1. **任务排程与指令预置**：获取当前本地时间，根据用户要求的 `{scheduled_time}` 计算触发点。使用 `task_create` 创建主任务，并配合 `cron` 设置定时触发器。在触发消息中明确“结果导向”要求：必须穷尽搜索且产出本地文件。
2. **多维潜客发现**：任务触发后，使用 `web_search` 或相关电商调研工具，针对 `{product_keyword}` 搜索活跃卖家或独立站。建议使用多组关键词（如 "top sellers", "distributors"）并行搜索以确保“穷尽”。
3. **联系人深度调研与核验**：对筛选出的目标执行背景调查（可结合 `brand-contact-research` 技能），挖掘官网、决策人（采购/运营）及已验证的业务邮箱，剔除无效联系方式。
4. **结构化本地持久化**：**（核心步骤）** 将公司名、网站、验证邮箱、负责人、主营业务等信息整理成结构化数据。必须使用 `bash` 或文件系统工具，在本地生成 `{filename}.csv` 或 `.xlsx` 文件，确保数据“已保存在电脑上”。
5. **任务汇报与发信核验**：向用户汇报本地归档文件的绝对路径。若涉及发信，核验 Gmail 的“已发送”记录（注意 Windows 命令行下的 JSON 转义问题）或准备好草稿，并汇总执行情况。

## Suggestions
- **Windows 语法加速**：在通过 `accio-mcp-cli` 调用工具时，若 `--json` 参数因双引号剥离报错，请改用 `--arg key val` 这种平铺参数的形式，或在 JSON 字符串中对双引号进行转义（如 `\"`）。
- **任务优先级管理**：为搜索、背调、归档分别创建子任务（Sub-tasks），方便在执行过程中实时汇报进度，符合“以结果为导向”的透明度要求。

## Fallback / Edge Cases
- **无结果容错**：若初步搜索无结果，必须尝试变换关键词或切换平台（如从 Amazon 转向 LinkedIn 或行业黄页），严禁直接回复“无法完成”。
- **权限受阻处理**：若无法写入系统根目录，应自动退回当前项目所在的文件夹进行暂存，并生成一个桌面快捷方式或提示用户手动迁移。

## Pitfalls
- **Step 4 (本地归档)**：严禁只在对话中输出表格而不生成实际文件，这违反了“数据留痕”的硬性要求。
- **Step 1 (Cron 设置)**：确保 `cron` 的 Payload 包含足够的上下文指令，否则触发后的 Agent 可能会丢失原始任务的目标和约束。
