## Workflow
1. **全球时区滚动排程**：根据目标市场（如美、加、英、德等）的当地起始工作时间，配置每日三轮 `{schedule_times}`（建议本地时间 09:00、16:00、22:00）的 Cron 定时任务，确保覆盖亚洲、欧洲及美洲市场。
2. **执行“极限测试”规模标准**：为每一轮任务设定明确的批量开发指标 `{batch_size}`（基准为 50 个高意向负责人），并在各轮次之间保留冗余时间用于系统自我优化和处理待办事项。
3. **多阶段自动化链条集成**：在每轮任务中，按照“平台卖家搜索 -> 联系方式挖掘 -> 邮箱 MX 验证 -> 个性化 HTML 草稿撰写 -> 批量投递”的顺序串联动作，确保全程闭环。
4. **Gmail 发信状态实效性验证**：在调用发信工具后，必须立即通过 `search_gmail_messages` 工具使用 `to:{recipient}` 或 `subject:"{subject}"` 查询发件箱。获取具体的 Message ID 及 Web Link 并反馈给用户，解决 API 发信在客户端“不可见”的疑虑。
5. **HTML 模板渲染与发送**：准备包含产品亮点、图片及 HTML 结构的开发信模板，发送时需特别处理特殊字符转义，避免触发执行环境解析错误。

## Suggestions
- **身份对齐**：在每轮定时任务的 payload 中明确指定发信身份（如：以 Miguel Yang 的身份发送），确保所有自动化邮件的落款和风格一致。
- **时区优势利用**：利用 22:00 轮次针对美加市场进行精准触达，通过时差优势让邮件出现在对方清晨的收件箱顶部。

## Pitfalls
- **Step 4: 搜索索引延迟**：Gmail API 发送的邮件在“已发送”标签中的索引可能存在数秒延迟。若立即搜索未果，应尝试使用更宽泛的 query（如仅搜主题词）或在 10 秒后重试。
- **Step 5: Shell 字符转义死锁**：直接在 shell 命令行中通过 `--json` 传递包含 `< >` 等标签的 HTML 字符串时，极易报出“此时不应有 <”等错误。必须将 HTML 内容写入临时文件或通过 Python 脚本加载后调用 API，禁止在命令行中硬编码复杂 HTML。

## Fallback / Edge Cases
- **目标盘符/路径受限**：在生成开发报告或留痕文件时，若遇到根目录写保护，应自动将资产暂存至项目工作目录，并生成一个 `.bat` 迁移脚本供用户后续手动归档。
